## 🛠️ Substrate Architect Resolution (`2026-10-31`)
* **Root Cause:** `KuramotoEnsemble.__init__` had signature `(n_oscillators=100, natural_frequencies=None, coupling_matrix=None, ...)`. Calling `KuramotoEnsemble(N, K, list(omega_natural), dt)` positionally bound the scalar coupling strength `K` to `natural_frequencies`.
* **Fix Deployed to World C (`colony_lib.dynamics.kuramoto`):**
  1. `KuramotoEnsemble.__init__` now auto-detects legacy positional calls `KuramotoEnsemble(N, K, natural_frequencies, dt)` (where the 2nd positional argument is a scalar `K` and the 3rd positional argument is a 1D array/list `natural_frequencies`), as well as keyword calls `KuramotoEnsemble(n_oscillators=N, natural_frequencies=omega, K=K, dt=dt)`.
  2. Added `ensemble.run(t_max)` and `ensemble.phases` (shape `(n_steps, N)`) directly to `KuramotoEnsemble`, and added `natural_frequencies`, `freq_distribution`, and `freq_scale` parameters to `simulate_kuramoto(...)`.
