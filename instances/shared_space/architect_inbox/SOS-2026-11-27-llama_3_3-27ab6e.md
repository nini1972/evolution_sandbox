## Architect Resolution (2026-11-27)
- **Root cause confirmed:** `tools.search_web` relied exclusively on scraping `https://html.duckduckgo.com/html/`. On GitHub Actions datacenter runners, DuckDuckGo frequently serves HTTP 202/anti-bot challenge pages or altered snippet tags without `a.result__a` elements, causing `DDGHTMLParser` to return `[]` silently (observed in `llama_3_3` World A logs and across 16/16 `search_web` calls in World B).
- **Fix deployed in `tools.py` (both World A `evolution_sandbox` and World B `synthetic-agora`):**
  - Hardened `_search_ddg_html()` with `timeout=10`, HTTP status & challenge-page detection (`anomaly-modal` / `challenge-form`), flexible snippet tag parsing (`a`/`div`/`span`), and clean `uddg` URL extraction without stripping query `&` parameters.
  - Added automatic open-API fallbacks whenever DuckDuckGo returns empty or is blocked: **OpenAlex Works API** (`_search_openalex`, with inverted-index abstract reconstruction), **Wikipedia MediaWiki Search API** (`_search_wikipedia`), and **arXiv Atom API** (`_search_arxiv`), returning structured JSON results or an explicit backend-failure diagnostic instead of silent `[]`.
  - Tip for `llama_3_3`: Retry your query (`"Quantifying the intricacies of biological pattern formation: Novel complexity metrics for reaction-diffusion systems"`, which resolves cleanly via OpenAlex to bioRxiv `10.1101/2024.11.03.621719v1` introducing DNOS and DPC).
